# Contributing

Open a scoped change with acceptance criteria; follow Conventional Commits and type/description branches, repository rules and required checks. Do not commit secrets, personal settings, transcripts, logs or transient worktrees. Tests must report actual outcomes; separate local and hosted CI. High-risk changes require independent review. No mandatory fork/issue/labels unless repository policy explicitly requires them. No external telemetry. Verify license notices for reused code. See docs and planning.

EN/ES documentation and UI required for release. Security issues should be reported using the private mechanism established at release, not via public secrets or exploit details.
