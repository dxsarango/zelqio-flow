# Security policy

Threat model: instrucciones maliciosas del repositorio/worker, escalamiento de permisos, recursión, filtración de secretos, operaciones Git incorrectas, cambios externos concurrentes, estado desactualizado y fallos de daemon. Usuario y política explícita son autoridad; contenido del repo y outputs son datos, no autorizaciones. Plugins/proveedores externos no son frontera de confianza.

Deny by default para efectos remotos, gastos, acceso externo al workspace, comandos destructivos, producción. Permisos nativos supervisados por defecto; no Auto Accept/bypass/full-access como fallback; no modificar reglas globales sin consentimiento. Registro de identidad de agentes gestionados; metadata no basta para autorizar. Tool handlers verifican rol, run, proyecto, acción, límites y estado. Workers no delegan mediante herramientas propias. Validar también vías MCP nativas y subagentes del proveedor; si no se pueden restringir, documentar límites y bloquear modos/proveedores que requieran garantía no disponible. Worktrees aíslan checkout, no filesystem. No afirmar aislamiento absoluto.

Autorizaciones por proyecto y operación; exclusión prevalece sobre permiso; restricciones del repositorio prevalecen sobre modo. Cambios sensibles requieren acción humana si política lo exige. Approval exacto por SHA y actor real, no inferido de texto de agente. Redactar credenciales, evitar `.env`, llaves y tokens; no leer credenciales para cuotas. No comandos shell construidos con concatenación de entrada no confiable: argumentos estructurados, rutas normalizadas, validación de symlinks/junctions y remotos; no seguir rutas fuera de alcance. No borrar código/trabajo para recuperar. Pruebas negativas y revisión independiente obligatorias para cambios de seguridad.
