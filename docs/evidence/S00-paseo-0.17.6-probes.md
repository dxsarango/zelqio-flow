# S00 — Sondas de Paseo 0.17.6 en Windows

**Avance.** Instalación, comparación y sondas P1–P3 y E1–E7 completadas. Quedan bloqueados por la plataforma la procedencia de la selección nativa, el archivado seguro de checkouts sucios, el acceso por cuenta y las notificaciones de cuota desde el plugin, y la creación de cron desde el SDK inyectado.

## Instalación y comparación

Windows, Node.js 24.21.0, npm 11.19.0, Git 2.50.1.windows.1. Los 39 archivos `.d.ts` en `@getpaseo/plugin/dist` y `@getpaseo/client/dist/index.d.ts` coincidieron byte a byte con 0.17.5. La ayuda de la CLI coincidió para la raíz, `agent run`, `agent send`, `workspace archive`, `plugin install`, `provider`, `schedule create` y `heartbeat create`. La comparación de ayuda fue local y sin daemon 0.17.5. [Sondas de 0.17.5](S00-paseo-0.17.5-probes.md).

## Ciclo con cuotas

Los veredictos corresponden a 0.17.6. La última columna distingue ejecución previa de coincidencia de contrato o implementación en 0.17.5. El plugin de prueba declaró `id` y `requirements.paseo` en `paseo-plugin.json`. El esquema del manifest carece de campos de permisos o capabilities para estas operaciones. El host aislado habilitó los plugins con `pluginsEnabled: true`. Las capacidades `prompt.message` y `session.persistence` se negociaron con el proveedor sintético. `useComposer` se importa de `@getpaseo/plugin/client`. El cliente de bajo nivel de E2 y E6 se obtiene mediante `createHostClient(endpoint, {clientId, clientType: "cli"})` de `@getpaseo/client/node` y `await client.connect()` sobre el loopback aislado.

### Reproducción

Preparar los paquetes en `<sandbox>/v0.17.6` con el comando de instalación de arriba. Fijar `npm_config_userconfig`, `npm_config_globalconfig` y `npm_config_cache` a ubicaciones de ese directorio. Para comparar la ayuda y declaraciones se necesita también el directorio de paquetes `<sandbox>/v0.17.5`. La comparación solo ejecuta `--help` en la CLI anterior. También coincidieron `client/dist/index.js`, `client/dist/daemon-client.{js,d.ts}` y los módulos inspeccionados de manifest, cuotas y despacho de mensajes en el servidor. Cuando falte `node_modules` en el worktree, copiar físicamente las dependencias fijadas del repositorio local. Las sondas se ejecutan en serie.

```powershell
$Sandbox = '<sandbox>'
$GitExe = (Get-Command git.exe).Source
$NodeDir = Split-Path (Get-Command node.exe).Source
$NpmCli = Join-Path $NodeDir 'node_modules/npm/bin/npm-cli.js'
$ChromeExe = '<chrome.exe>'
$Driver = 'poc/paseo-0.17.6/run.mjs'
$Stamp = Get-Date -Format 'yyyyMMdd-HHmmss'
node poc/paseo-0.17.6/compare.mjs $Sandbox $GitExe
node $Driver $Sandbox "run-compatibility-$Stamp" $GitExe compatibility $NpmCli (Get-Location).Path
node $Driver $Sandbox "run-browser-$Stamp" $GitExe browser $ChromeExe
node $Driver $Sandbox "run-retirement-$Stamp" $GitExe retirement
node $Driver $Sandbox "run-loop-$Stamp" $GitExe loop
npm run check
```

Cada fase usa `<sandbox>/home-0176/<run>` nuevo, perfil de usuario sintético, relay desactivado y `127.0.0.1:16775`. El navegador Chrome 158.0.8127.37 usa un perfil nuevo, el proxy web de prueba en 16776 y CSP acotada al origen aislado. El runner apunta la salida de red compatible con proxy al puerto cerrado 16777 y guarda `features.dictation.enabled: false` y `features.voiceMode.enabled: false` en el home aislado. En repeticiones con el proxy ya activo, las solicitudes de descarga en segundo plano recibieron `ECONNREFUSED` en ese puerto. Un arranque anterior intentó descargar el modelo local de dictado por defecto y dejó el listener temporal levantado tras expirar el comando de inicio. Se confirmó el PID mediante `daemon status` con el home de esa prueba y se detuvo con `daemon stop`. La última prueba de compatibilidad confirmó en el log que voz y dictado estaban desactivados, sin inicio de descarga. El runner reintenta la detención en `finally` y comprueba ambos listeners. **Presupuesto real de inferencia: 0 prompts a proveedores externos.** Los únicos mensajes del ensayo fueron sintéticos.

La ejecución final de `loop` salió con código 0 con voz y dictado desactivados en los tres arranques. El cron de control positivo se restauró para las 07:51 UTC y produjo un run `succeeded`. El control caducado produjo cero runs y el reintento del mismo mensaje tras el segundo reinicio produjo cero prompts adicionales.

El listener habitual `127.0.0.1:6767` conservó PID 3332, observado exclusivamente en la tabla TCP. Al terminar, los puertos de prueba 16775–16777 quedaron sin listeners. El worktree de evidencia pasó `npm run check` con 383 pruebas en 33 archivos.
